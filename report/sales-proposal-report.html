Bắt đầuGetting started

Biến một cái tên khách hàng thành đề xuất bán hàng hoàn chỉnhTurn a client name into a complete sales proposal

technext-sales-proposal là một Agent Skill: đưa vào tên công ty, website hoặc một brief ngắn, nhận về một website đề xuất song ngữ (VI/EN) tự chứa — phủ cả ba dòng dịch vụ Odoo ERP, AI Solutions và Social Media Marketing.technext-sales-proposal is an Agent Skill: give it a company name, a website, or a short brief, and it returns one self-contained bilingual (VI/EN) proposal website — covering all three TechNext service lines: Odoo ERP, AI Solutions, and Social Media Marketing.

Điều skill cố ý không làmWhat the skill deliberately won't do

  • Không bịa số. Số không đọc được thì ghi null + lý do, không ghi 0 như thể là dữ liệu thật.No invented numbers. A metric it could not read is written as null plus a reason — never as 0 pretending to be data.
  • Không dùng CDN. Đề xuất giao cho khách phải mở được khi offline.No CDN. A proposal handed to a client must open while offline.
  • Không cần API key trả tiền. Định danh doanh nghiệp dùng GLEIF, Wikidata, Companies House, OpenCorporates, SEC EDGAR — đều miễn phí.No paid API keys. Entity lookups use GLEIF, Wikidata, Companies House, OpenCorporates and SEC EDGAR — all free.
  • Không vượt tường chặn. Login wall hay Cloudflare thì ghi nhận là nguồn không truy cập được, không tìm cách lách.No bypassing walls. A login wall or Cloudflare means the source is recorded as unreachable, not circumvented.

Cài đặtInstall

Clone repo ra cạnh (không phải bên trong) thư mục skills của agent, rồi chạy installer:Clone the repo next to — not inside — your agent's skills directory, then run the installer:

git clone https://github.com/aidev3-web/technext-sales-proposal.git
pwsh -File install.ps1                 # Windows
./install.sh                           # macOS / Linux

Installer tạo liên kết cho skill gốc + 10 sub-skill vào thư mục skills bạn chọn, vì pipeline gọi sub-skill theo tên nên chúng phải tự tìm thấy được. Thư mục thật đang tồn tại sẽ không bị ghi đè — chỉ báo và bỏ qua.The installer links the orchestrator skill plus its 10 sub-skills into the skills directory you choose, because the pipeline dispatches sub-skills by name — they must be discoverable on their own. An existing real folder is never overwritten; it is reported and skipped.

  • -Destination <path> — chọn thư mục skills; bỏ trống thì installer liệt kê các thư mục nó tìm thấy.pick the skills directory; if omitted the installer lists the ones it finds.
  • -Copy — copy file thay vì tạo liên kết (khi junction/symlink không dùng được).copy files instead of linking (when junctions/symlinks aren't available).
  • -SkipSubSkills / -DryRun — chỉ cài skill gốc / xem trước mà không đụng gì.orchestrator only / preview without touching anything.

Máy mới tinh, chưa có repo: copy nội dung BOOTSTRAP-PROMPT.md đưa cho agent — agent tự cài vào chính nó rồi tự kiểm tra lại.On a fresh machine with no clone yet: hand the contents of BOOTSTRAP-PROMPT.md to the agent — it installs the skill into itself and verifies the result.

Vì sao pipeline hiện tại làm nó tệ hơnWhy the current pipeline makes it worse

Phase 0.8 (web-osint-scanner) đẩy mọi URL tìm được qua Jina Reader và lưu text vào captures/<sha1>.md; captures/manifest.json chỉ có hai trường: file và fetched_at. Không có khái niệm "bị chặn". Nghĩa là một trang đăng nhập được cache y hệt một trang nội dung thật, rồi cả 4 nhóm nghiên cứu đọc lại nó như dữ liệu đã kiểm chứng. Cộng với việc một chỉ số không đọc được dễ bị ghi thành 0, ta có thể giao cho khách một con số sai thay vì một khoảng trống trung thực.Phase 0.8 (web-osint-scanner) pushes every discovered URL through Jina Reader and stores the text in captures/<sha1>.md; captures/manifest.json carries just two fields: file and fetched_at. There is no notion of "blocked". So a login page is cached exactly like a real content page, and all four research groups then read it as if it were verified data. Combined with the ease of writing 0 for a metric that could not be read, we can hand a client a wrong number instead of an honest gap.

Luật đã chốt: không bao giờ ghi 0 cho một chỉ số không đọc được. Phải là null kèm lý do. Một chỉ số thiếu thì sửa được; một chỉ số sai thì phá cả bản đề xuất.Rule already agreed: never write 0 for a metric that could not be read. It must be null with a reason. A missing number can be fixed; a wrong number destroys the whole proposal.

Lời giải — bốn lớp, đã kiểm chứng bằng thử nghiệm thậtThe solution — four layers, verified by real tests

Không phải đề xuất trên giấy: mỗi lớp dưới đây đều đã được chạy thử từ máy này, kèm kết quả đo được và cả chỗ nó hỏng.Not a paper proposal: every layer below was actually run from this machine, with measured results and the places it still breaks.

  1. 1
    Thu hoạch từ chỉ mục tìm kiếm — chạy được ngay, không cần quyền gìHarvest from a search index — works today, needs no permissionđã chạy đượcverified working

    Brave Search trả HTTP 200 và cho ngay thứ mình cần: điểm đánh giá, số lượng review, xếp hạng, và trích đoạn nguyên văn của review. Nó cũng là cách tìm ra URL gốc — trang TripAdvisor, page Facebook của khách — mà không phải mò. Nguyên tắc: không mở trang bị chặn, chỉ đọc phần mà chỉ mục công khai đã lưu sẵn.Brave Search returns HTTP 200 and hands over exactly what we need: the rating, the review count, the ranking, and verbatim review excerpts. It is also how we find the canonical URLs — the TripAdvisor page, the client's Facebook page — without guessing. The principle: never open the blocked page, only read what the public index already stored.

    Chỗ hỏng đo được: Brave bắt đầu trả 429 sau 2–4 truy vấn liên tiếp. Nên thiết kế phải có giãn nhịp + cache, và khi chạy thật thì dùng Brave Search API (có key, có free tier) thay vì đọc HTML.Measured failure: Brave starts returning 429 after 2–4 back-to-back queries. So the design needs pacing plus a cache, and in production it should use the Brave Search API (keyed, with a free tier) rather than scraping HTML.

  2. 2
    API chính thức bằng token của chính khách hàng — cửa duy nhất để có review đầy đủ và mớiOfficial APIs with the client's own token — the only door to full, current reviewscần khách cấp quyềnneeds client consent

    Chỉ mục tìm kiếm cho trích đoạn; chỉ API mới cho toàn văn, đủ số lượng, và mới nhất. Meta Graph API cho ratings và feed + comment của page; Instagram Graph API cho comment; Reddit OAuth (miễn phí, chỉ cần đăng ký app); Google Business Profile API cho review Google. Đã kiểm chứng: gọi Graph API không token trả 400 OAuthException — xác nhận đây là cửa cần quyền, không phải cửa hỏng.A search index gives excerpts; only APIs give full text, complete counts, and freshness. Meta Graph API for page ratings and feed + comments; Instagram Graph API for comments; Reddit OAuth (free, just register an app); Google Business Profile API for Google reviews. Verified: calling the Graph API with no token returns 400 OAuthException — confirming this is a door that needs permission, not a broken door.

    Việc phải làm: biến "xin token hoặc bản export" thành một bước chuẩn ở Phase 0, kèm mẫu câu hỏi sẵn. Đây là thay đổi quy trình, không phải thay đổi code.What to do: make "ask for a token or an export" a standard Phase 0 step, with a ready-made request template. That is a process change, not a code change.

  3. 3
    Kho lưu trữ công khai — dùng được, nhưng không đáng tin để làm đường chínhPublic archives — usable, but not dependable as the main roadchập chờnflaky

    Wayback có snapshot thật của trang TripAdvisor của khách (bản 2019) — API kiểm tra tồn tại chạy tốt. Nhưng tải nội dung thì hỏng: IP này bị 429 sau vài chục request, và Jina chặn hẳn web.archive.org (báo tới 2035, lý do "nghi ngờ DDoS").Wayback does hold a real snapshot of the client's TripAdvisor page (a 2019 capture) — the availability API works fine. But fetching content breaks: this IP gets 429 after a few dozen requests, and Jina blocks web.archive.org outright (until 2035, reason: "suspected DDoS").

    Kết luận: giữ làm nguồn bổ sung, luôn ghi ngày chụp, và không bao giờ để nó là đường duy nhất.Conclusion: keep it as a supplementary source, always record the capture date, and never let it be the only road.

  4. 4
    Phát hiện chặn + khai báo khoảng trốngBlock detection + declaring the gapchưa làmnot built yet

    Như đã thiết kế: phân loại login_wall / cf_challenge / datadome / rate_limit, ghi blocked_reason vào manifest, không bao giờ ghi 0. Bổ sung sau khi đo: 429 và 403 phải được ghi là rate_limit, không phải "không có dữ liệu" — vì hôm nay chính Brave, archive.org và Jina đều trả 429/403 khi bị gọi nhanh. Đây là lớp bắt buộc: không có nó, ba lớp trên có thể âm thầm biến "bị chặn" thành "bằng 0".As designed: classify login_wall / cf_challenge / datadome / rate_limit, write blocked_reason into the manifest, never write 0. Added after measuring: 429 and 403 must be recorded as rate_limit, not "no data" — because today Brave, archive.org and Jina all returned 429/403 when called quickly. This layer is mandatory: without it, the three layers above can silently turn "blocked" into "zero".
